# Система управления клиникой

Курсовой проект: REST API (Node.js, Express, Sequelize, PostgreSQL) и клиент на React.
Ветка **`25`** — лабораторная работа №5: интеграция React-клиента с REST API.

```
.
├── server.js, routes/, controllers/, models/, ...   REST API (лабораторные 1–3)
├── migrations/, seeders/                            схема БД и демонстрационные данные
└── client/                                          React-клиент (лабораторные 4–5)
```

## Запуск

Нужны Node.js 20+ и доступная база PostgreSQL.

### 1. Сервер (порт 3000)

В корне репозитория создайте файл `.env` (в git он не попадает) со значениями:

| Переменная | Что это |
| --- | --- |
| `DATABASE_URL` | строка подключения к PostgreSQL |
| `DB_SSL` | `true`, если сервер БД требует SSL, иначе `false` |
| `PORT` | порт API, по умолчанию `3000` |
| `JWT_SECRET` | секрет подписи токенов, не короче 32 символов |
| `JWT_EXPIRES_IN` | срок жизни токена, например `1h` |
| `TOTP_ENCRYPTION_KEY` | 64 hex-символа, ключ шифрования секретов Google Authenticator |
| `TOTP_ISSUER` | название приложения в Google Authenticator |
| `APP_BASE_URL` | адрес сервера для ссылки в письме, `http://localhost:3000` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` | почта для писем с подтверждением (Gmail, пароль приложения) |
| `CLIENT_ORIGIN` | необязательно: адрес клиента для CORS, по умолчанию `http://localhost:5173` |

```bash
npm install
npm run db:migrate     # создать таблицы
npm run db:seed        # демонстрационные данные (врачи, пациенты, записи)
npm run dev            # http://localhost:3000
```

### 2. Клиент (порт 5173)

```bash
cd client
npm install
npm run dev            # http://localhost:5173
```

Адрес API задаётся в `client/.env` (`VITE_API_URL=http://localhost:3000`).

### 3. Как проверить

1. Откройте http://localhost:5173. Без входа видны врачи и свободные талоны: выберите врача, дату, время и нажмите «Записаться».
2. Регистрация (3 шага на одной странице): почта и 6-значный код из письма → анкета пациента → пароль. После создания пароля откроется главная с окном входа справа.
3. После входа в шапке видны имя, кружок с меню (медицинская карта, мои талоны, история болезни, настройки) и кнопка «Выйти».
4. «Настройки» → «Google Authenticator»: QR-код, ввод кода, при следующем входе код потребуется. Там же смена почты (по коду) и пароля.
- Вход возможен по почте или по номеру телефона. Телефон везде в строгом формате `+375(44)4444444`: маска с префиксом показывается всегда, лишние цифры ввести нельзя.
- У пациента не больше 4 активных талонов. Талон можно перенести на другое свободное время и изменить его описание («Мои талоны» → «Изменить»).
- На главной справа «Доска почёта»: три случайных врача (меняются при каждом обновлении страницы), кнопка «Подробнее» открывает профиль врача. Профили статические и лежат в `client/src/data/doctorProfiles.js`. Фотографии врачей (`client/public/doctors`) сгенерированы нейросетью StyleGAN, источник — thispersondoesnotexist.com; изображённых людей не существует.
- Из формы записи кнопка «Подробнее о враче» ведёт в профиль; вернуться можно по хлебным крошкам, выбранные врач, дата и время сохраняются.

6. Сотрудник регистратуры (аккаунт с ролью `staff`) видит в шапке пункт «Регистратура»: там полный список записей, оптимистичные операции и retry из лабораторной №5. Остановите сервер и повторите действие, чтобы увидеть повторные попытки и откат.

#### Роли и миграции

В базе добавлена роль пользователя (`users.role`). После `npm run db:migrate` все **существующие** аккаунты становятся сотрудниками (`staff`), новые, зарегистрированные пациентами, получают `patient`. Пациенту недоступны общие списки `/patients` и `/appointments` (ответ 403). Дать роль сотрудника можно запросом:

```sql
UPDATE users SET role = 'staff' WHERE email = 'name@mail.by';
```

Старые маршруты регистрации по ссылке (`/auth/register`, `/auth/verify-email`, `/auth/resend-verification`) заменены на `/auth/register/start`, `/auth/register/verify`, `/auth/register/complete`.

## Что реализовано в лабораторной работе №5

- **CORS** на сервере (`server.js`, пакет `cors`): клиент на другом порту получает доступ к API, разрешён заголовок `Authorization`.
- **`client/src/api.js`**: экземпляр axios, интерцептор запроса добавляет `Authorization: Bearer <JWT>` из `localStorage`, функции `fetchAppointments`, `addAppointment`, `updateAppointment`, `patchAppointment`, `deleteAppointment`.
- **Список с состояниями**: спиннер при загрузке, сообщение об ошибке и кнопка «Повторить», загрузка один раз при открытии (`useEffect`) с отменой запроса через `AbortController`.
- **Оптимистичные обновления** (`client/src/hooks/useAppointments.js`): добавление (временный `id = Date.now()`, замена на настоящий, откат при ошибке), удаление и редактирование (откат при ошибке), уведомления об ошибках.
- **Улучшение «Повтор запроса при ошибке (retry)»**: до 3 попыток с задержкой 1 с и 2 с, индикатор «попытка N из 3».
- **JWT**: токен сохраняется в `localStorage` после входа и подставляется автоматически; при ответе 401 пользователь возвращается на экран входа.
- Личный кабинет пациента: регистрация с подтверждением почты кодом, запись на свободные талоны, медицинская карта, мои талоны (активные и архив), настройки (почта, пароль, Google Authenticator). Регистраторская часть с CRUD записей находится по адресу `/staff`.

## MongoDB (лабораторная работа №6, ветка `26`)

MongoDB дополняет PostgreSQL: **медицинская карта** хранится в ней одним документом. В PostgreSQL эти данные разложены по таблицам `patients`, `medical_records`, `medical_entries` и `discharges`, а в MongoDB пациент, диагнозы, препараты и все приёмы с назначениями лежат во вложенных объектах и массивах одного документа.

### Подключение

1. Установите MongoDB Community Server (или создайте бесплатный кластер M0 в MongoDB Atlas и пользователя базы данных).
2. Добавьте в `.env` строку подключения:

| Переменная | Пример |
| --- | --- |
| `MONGO_URI` | `mongodb://127.0.0.1:27017/clinic` (локально) или `mongodb+srv://<user>:<password>@<cluster>.mongodb.net/clinic` (Atlas) |

3. Запустите сервер: `npm run dev`. В консоли появится `MongoDB connected`. Без `MONGO_URI` или при недоступной базе сервер всё равно запускается, а маршруты `/mongo/*` отвечают 503.
4. По желанию перенесите данные из PostgreSQL: `npm run mongo:seed` (повторный запуск безопасен).

### Файлы

| Файл | Назначение |
| --- | --- |
| `config/mongo.js` | подключение Mongoose, состояние соединения |
| `mongo/models/MedicalCard.js` | схема карты: вложенный объект `patient`, массивы `allergies`, `tags`, вложенные документы `diseases`, `medications`, `visits` (внутри приёма ещё `vitals` и массив `prescriptions`), индексы, виртуальные поля, методы и статические методы, каскадное удаление |
| `mongo/models/LabResult.js` | анализы: отдельная коллекция со ссылкой на карту (`populate`) |
| `mongo/controllers/cardsController.js` | CRUD, операции над вложенными массивами, агрегации |
| `mongo/routes/cards.js` | маршруты `/mongo/*` |
| `scripts/seedMongo.js` | перенос данных из PostgreSQL |

### Маршруты (нужен вход сотрудником, кроме `/mongo/health`)

| Метод и адрес | Что делает | Операция MongoDB |
| --- | --- | --- |
| `GET /mongo/health` | состояние подключения | — |
| `GET /mongo/cards` | список (`q`, `tag`, `disease`, `bloodType`, `sort`, `page`, `limit`) | `find().where().select().sort().skip().limit()` |
| `GET /mongo/cards/:id` | карта вместе с анализами | `findById().populate()` |
| `POST /mongo/cards` | создать карту (можно только `patientId`) | `create()` |
| `PUT /mongo/cards/:id` | изменить поля | `findByIdAndUpdate(..., { new: true })` |
| `DELETE /mongo/cards/:id` | удалить, вернуть документ, удалить анализы | `findByIdAndDelete()` + хук |
| `POST /mongo/cards/:id/visits` | добавить приём | `push` во вложенный массив |
| `PATCH /mongo/cards/:id/medications/:medId` | изменить один препарат | `$set` с позиционным оператором `$` |
| `POST /mongo/cards/:id/visits/:visitId/prescriptions/extend` | продлить курс препарата | `$inc` + `arrayFilters` |
| `POST /mongo/cards/:id/diseases`, `DELETE .../diseases/:diseaseId` | добавить и убрать заболевание | `$push`, `$pull` |
| `POST /mongo/cards/:id/tags`, `DELETE .../tags/:tag` | метки без дубликатов | `$addToSet`, `$pull` |
| `GET`, `POST /mongo/cards/:id/labs` | анализы карты | вторая коллекция |
| `GET /mongo/stats/doctors`, `GET /mongo/stats/diagnoses` | статистика | `aggregate`: `$unwind`, `$group`, `$project`, `$sort` |

Готовые запросы для проверки лежат в конце файла `requests.http`. Данные смотрите в MongoDB Compass (база `clinic`, коллекции `medicalcards` и `labresults`).

## Кабинет врача «Моя клиника» (ветка `26`)

Врач входит по адресу `/doctor/login` (ссылка «Я врач» в подвале сайта «Твой талон»). Аккаунты врачей создаются из таблицы `doctors`:

```
npm run db:migrate                                   # новая миграция: рост, вес, аватар, doctor_id у users
npm run doctors:accounts                             # случайные пароли -> doctor-passwords.local.txt (в .gitignore)
npm run doctors:accounts -- --password=Qwerty123!    # или один общий пароль для всех
```

Логин врача — его e-mail из таблицы `doctors`. Вход в кабинет врача идёт отдельным запросом `POST /auth/doctor/login` (пациенту или регистратору он ответит 401). Дальше 2FA работает так же, как у пациентов.

| Метод и адрес (нужна роль `doctor`) | Что делает |
| --- | --- |
| `GET /doctor/me` | данные врача |
| `GET /doctor/appointments?period=today\|upcoming\|past\|all&status=` | записи к этому врачу |
| `GET /doctor/patients/:id` | профиль пациента из PostgreSQL и признак личного дела |
| `GET /doctor/patients/:id/avatar` | своё фото пациента (если загружал) |
| `POST /doctor/patients/:id/card` | создать личное дело в MongoDB из профиля |
| `GET`, `PATCH /doctor/patients/:id/card` | прочитать и дополнить дело (профиль, замеры, анамнез, списки) |
| `POST /doctor/patients/:id/card/visits` | добавить приём (жалобы, осмотр, диагноз, назначения); запись на приём получает статус «проведён» |
| `POST /doctor/patients/:id/card/referrals` | выписать направление |
| `GET /doctor/patients/:id/card.docx` | Word: медицинская карта (фото 3×4 или рамка «Нет фото») |
| `GET /doctor/patients/:id/referrals/:referralId.docx` | Word: направление с шапкой и местом для печати |

Врач видит только пациентов, записанных к нему (иначе 403). Данные личного дела лежат в MongoDB документом (вложенный пациент, массивы приёмов и направлений), Word-файл строится из этого документа в момент скачивания. Печать на сайте идёт через системное окно печати браузера.

Аватар пациента: `PUT /me/avatar/preset` (один из 9 готовых аватаров), `PUT /me/avatar/photo` (тело — файл JPEG, PNG или WebP до 8 МБ, не меньше 120×120; сервер через `sharp` поворачивает по EXIF, обрезает до квадрата, уменьшает до 480×480 и сохраняет JPEG), `GET /me/avatar`, `DELETE /me/avatar`. Рост и вес — `PATCH /me/record` (`heightCm`, `weightKg`).

### Администратор и открытие доступа врачам

```
npm run admin:create                         # логин admin, пароль admin (только для разработки)
ADMIN_PASSWORD=Свой!Пароль1 npm run admin:create   # на сервере задайте свой пароль
```

Администратор входит на `/doctor/login` с логином `admin`. У него доступ и к врачебному кабинету (записи всех врачей, любые пациенты и их личные дела), и к регистратуре. Повторный запуск скрипта меняет пароль существующего администратора.

Новому врачу доступ открывает только администратор: «Настройки» → «Добавить новый доступ» → почта → «Добавить» (`POST /doctor/access`). Сервер создаёт аккаунт врача, сразу записывает его в базу со случайным паролем и отправляет письмо «Вам открыт доступ к сервису» с ролью, почтой, паролем и кнопкой «Войти» (ведёт на `/doctor/login`). Если письмо не ушло, аккаунт не сохраняется. Если почта совпадает с почтой врача из таблицы `doctors`, аккаунт привязывается к его карточке. Для отправки писем в `.env` должны быть заданы `SMTP_USER` и `SMTP_PASS`.

Профиль врача (`/doctor/profile`) пока только для чтения: данные берутся из справочника врачей и описания врача, редактирование будет позже.

### История болезни пациента

Приёмы, которые врач оформил в личном деле, пациент видит в «Моя история болезни» (GET /me/history, GET /me/history/:visitId). У каждого приёма открывается документ и направления, выписанные в тот же день этим врачом, их можно скачать в Word (.../visit.docx, .../referrals/:referralId.docx) и распечатать. В саму медицинскую карту пациента направления не попадают.

### Талоны и карта пациента

- Пациент удаляет отменённые и прошедшие талоны (`DELETE /me/appointments/:id`) или очищает архив (`DELETE /me/appointments`). Талон скрывается только из списка пациента (колонка `appointments.patient_hidden`, нужна миграция `npm run db:migrate`), врач и клиника его по-прежнему видят. Предстоящий активный талон сначала нужно отменить.
- Диагноз и назначения, которые врач вносит в приём, автоматически попадают в медицинскую карту пациента: в его кабинете («Заболевания» и «Принимаемые препараты») и в личное дело в MongoDB. Повторы не добавляются. Для приёмов, оформленных раньше, один раз выполните `npm run records:sync`.

### Два отдельных входа

Сайт пациентов «Твой талон» и кабинет врача «Моя клиника» работают как два независимых клиента:

| | Сайт «Твой талон» | Кабинет «Моя клиника» |
| --- | --- | --- |
| Адрес | `/` | `/doctor/login` |
| Запрос входа | `POST /auth/login` | `POST /auth/doctor/login` |
| Код 2FA | `POST /auth/login/2fa` | `POST /auth/doctor/login/2fa` |
| Кто входит | пациенты и сотрудники регистратуры (`patient`, `staff`) | врачи и администратор (`doctor`, `admin`) |

Учётка чужого входа получает ответ «неверный логин или пароль», как будто её нет. Временный токен 2FA выдаётся для одного из входов и подтверждает код только на нём. В браузере у каждого входа свой токен (`clinic.site.token` и `clinic.doctor.token`), поэтому можно одновременно быть пациентом на сайте и врачом в кабинете, а выход из одного не затрагивает другой.

### Синхронизация карты между PostgreSQL и MongoDB

Данные карты пациента лежат в двух базах: личное дело врача (MongoDB) и карта в кабинете пациента (PostgreSQL). Общие данные при любом изменении в одной базе переносятся в другую (`services/cardSync.js`):

| Что | Из личного дела (MongoDB) → в кабинет пациента | Из кабинета пациента → в личное дело |
| --- | --- | --- |
| Группа крови, рост, вес | `PUT /mongo/cards/:id`, правка врача | `PATCH /me/record` |
| Заболевания, препараты | `POST` и `DELETE .../diseases`, `POST` и `PATCH .../medications`, правка врача, приём | `PATCH /me/record` |
| Аллергии | `PUT /mongo/cards/:id`, правка врача | – (пациент их не редактирует) |
| Адрес, работа, полис, статус, доверенное лицо | правка врача | `PATCH /me/patient` (обновляется вся анкета) |

Точечные операции (добавить или убрать одно заболевание или препарат) правят в кабинете пациента только эту строку, остальное не затрагивается. Карта без настоящего пациента в PostgreSQL (например, демонстрационная с `patientId` 101) работает как обычно, только никуда не переносится. Группа крови, изменённая врачом, не блокирует пациента на неделю.

### Демонстрационные пациенты

```
npm run patients:seed                         # 10 пациентов с аккаунтами; логины и пароли -> patient-passwords.local.txt
npm run patients:seed -- --password=Qwerty1!  # один общий пароль для всех
npm run patients:seed -- --passwords          # выдать новые пароли уже созданным
npm run patients:reset                        # удалить демо-пациентов со всеми данными и создать заново
```

Файл `patient-passwords.local.txt` (ФИО, логин, телефон, пароль) лежит в корне проекта и не попадает в git. Входят на сайт «Твой талон» по почте вида `kozlov@talon.example` или по телефону. У каждого демо-пациента заполнены анкета, группа крови, рост, вес, аллергии, заболевания и препараты, есть предстоящая запись к врачу и у части прошедший приём (нужны врачи в справочнике: `npm run db:seed`). Сброс удаляет только демо-пациентов (почта на `@talon.example`): их записи, карту, личное дело в MongoDB и аккаунт. Остальные пациенты не затрагиваются.
